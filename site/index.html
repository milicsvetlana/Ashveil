01 / ASHVEIL

A persistent world built around preparation, exploration and survival.

Ashveil began as an object-oriented programming university project and grew into a multi-system desktop game with combat, enemy AI, crafting, farming, area travel, narrative guidance and persistent save state.

05 / PREPARE

Gather. Craft. Build.

Inventory, crafting, farming and placement are connected to the same persistent world state rather than existing as isolated UI features.

Inventory

Persistent items

Stacking, hotbar selection, drops and chest-to-player transfers.

Crafting

Recipe driven

Recipes define material requirements without embedding crafting rules in the UI.

Farming

World state

Tilled ground, growth stages and harvest results persist with the active area.

Building

Validated placement

Dedicated targeting logic verifies placement before the world is modified.

06 / CECA

Guidance without a permanent quest list.

Ceca appears contextually as the player progresses. Gameplay systems emit events, the guidance system determines the relevant step, and the UI presents the message.

Gameplay Event → GuidanceSystem → GuideStep → Guidance UI

07 / UNDER THE HOOD

Built as a game,
structured as software.

The project separates rendering, input, UI, gameplay, navigation, persistence and progression so individual systems can evolve without turning the game loop into one large class.

01

AI & Navigation

BFS-generated distance fields with shared navigation infrastructure and specialized enemy behavior.

02

Async Persistence

Background file I/O keeps disk access away from the render loop while world reconstruction remains separate.

03

Persistent Areas

Each area can preserve farming, world objects, enemies, projectiles and encounter state independently.

04

State Machines

Special encounters such as Crimson Veil and Ashen Rite use explicit state rather than scattered flags.
